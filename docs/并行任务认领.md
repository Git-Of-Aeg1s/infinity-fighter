# 并行任务认领看板（先认领后动手）

> **目的**：多 AI 窗口共用一个工作区时的「事前避让」防线——动手前查表避让，而不是事后靠 git status 猜。设计依据见《并行开发改造设计.md》§4。

## 使用规则（铁律）

1. **先认领后动手**：窗口动手改任何 `js/`、`index.html`、`tools/` 文件前，先在下表登记一行；**登记即占用**，同文件冲突时先登记者优先，后到窗口必须换文件或等注销。
2. **登记粒度 = 文件**：只写将要修改的文件（新文件写预定名），禁止「全项目」式占坑；中途发现要改未登记文件，**先补登记再动手**。
3. **注销即交付**：收工（三连全绿）后**直接删除本行**即完成注销，不在本表留痕；完成情况写进收工报告与 commit message，不入表存档。
4. **认领不豁免验证**：登记了也要跑三连（check-names / check-syntax / smoke），认领表不是免检牌。
5. 与其他登记处的关系：本表是「事前避让」；`错误与待优化.md` 仍是「事后登记」，两者不互替。
6. 基线 commit 填登记时刻的 `git log -1 --format=%h`，便于判断「我认领之后对方有没有动过」。
