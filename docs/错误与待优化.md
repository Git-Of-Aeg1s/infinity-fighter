# 错误 / 待优化登记表

> **用途**：各 AI 窗口在开发中发现**不在自身职责范围内**的错误或可优化项时，**不要直接改**，登记到本文件，留给对应职责的窗口 / 后续任务认领处理。
>
> **不计入**：其他窗口**改了一半的半成品**导致的报错（如冒烟测试挂在别人未完成的功能上）——那不是错误，是进行中的工作；等其完成后若问题仍存在，再登记。

## 登记规则（给所有 AI 窗口）

1. **先判断是不是半成品**：登记前看 `git status` / `git diff`——若报错位置正处于其他窗口未提交的改动中，**不登记**（进行中的工作不算错误）。
2. **登记格式**：在下方表格追加一行，编号递增。描述要让不熟悉该区域的窗口能定位：文件 + 函数/行号 + 现象 + 复现方式（跑哪个场景 / 哪条命令能撞上）。
3. **登记 ≠ 顺手修**：登记后不要在本次任务里顺手修掉（除非该问题恰在你职责范围内，且用户知情同意）。
4. **认领修复**：修完后在「状态」列标 ✅ 已修复（日期 + 窗口标识），并跑通 `node tools/check-names.js` + `node tools/smoke.js`；若属移动/速度类问题，还须按 AGENTS.md 铁律实际跑帧观察。
5. **误报 / 决定不改**：标注 ⛔ 已否决 + 一句话理由，**保留该行**不删（留痕）。
6. 新窗口开工前扫一遍本表，避免踩已知坑；本文件与 AGENTS.md 同为必读。
